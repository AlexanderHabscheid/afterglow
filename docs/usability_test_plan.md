# Usability Test Plan

This is the plan I would run immediately after building the first feature.

## Objective

Check whether the post-date check-in feels fast, clear, and safe.

## Prototype to test

- `/demo/check-in`

## Tasks

1. Complete a check-in after a good date.
2. Complete a check-in after a mixed date.
3. Explain what the app should do next in each case.

## Questions after the task

1. What felt easy?
2. What felt awkward or unclear?
3. Which question mattered most?
4. Would you prefer this by SMS or in-app?
5. How would you expect the app to use this information?

## Metrics

- completion time
- completion rate
- confusion around any field
- willingness to submit after a real date
- reaction to an automated second-date nudge

## Design decisions this test should validate

- 5 fields is still lightweight enough
- comfort deserves its own question
- follow-up intent should remain separate from overall rating
